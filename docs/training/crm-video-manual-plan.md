

# แผนอัดวิดีโอคู่มือการใช้ระบบ CRM

เอกสารนี้ใช้เป็นแผนถ่ายทำวิดีโอคู่มือแบบแบ่งตอนสำหรับทีมร้านยา ผู้ดูแลร้าน เภสัชกร แอดมิน และทีมการตลาด โดยเน้นการใช้งานจริงในระบบ ไม่รวมขั้นตอนเชิงเทคนิค การแก้โค้ด ฐานข้อมูล หรือคำสั่ง deploy

## เป้าหมายของชุดวิดีโอ

- ให้พนักงานใหม่ดูจบแล้วเข้าใจภาพรวม CRM และเริ่มทำงานประจำวันได้
- แยกวิดีโอเป็นตอนสั้น เพื่อให้เปิดดูเฉพาะงานที่ต้องทำได้
- ใช้ภาษาหน้าร้าน อ่านง่าย อธิบายจากสถานการณ์จริง
- ลดการอธิบายซ้ำเรื่องแชท ลูกค้า แท็ก ประวัติยา การจ่ายยา และรายงาน

## รูปแบบมาตรฐานของทุกคลิป

- ความยาวแนะนำ: 4-8 นาทีต่อคลิป
- เปิดคลิป: บอกว่างานนี้ใช้เมื่อไหร่ และคนดูจะทำอะไรได้หลังดูจบ
- เนื้อหา: เดินหน้าจอจริงทีละขั้น ไม่เล่าเชิงระบบนานเกินไป
- ปิดคลิป: สรุป 3 จุดจำ และบอกคลิปถัดไปที่เกี่ยวข้อง
- หลีกเลี่ยง: ข้อมูลลูกค้าจริง เบอร์โทรจริง ยอดเงินจริง เลขออเดอร์จริง หรือข้อมูลสุขภาพจริง
- ถ้าต้องใช้ข้อมูลจริง: เบลอชื่อ เบอร์โทร line_user_id ที่อยู่ โรคประจำตัว แพ้ยา และประวัติยา

## ชุดที่ 1: ภาพรวม CRM

### ตอนที่ 1: CRM คืออะไร และทีมแต่ละคนใช้ส่วนไหน

เส้นทางหลัก: `/dashboard`, `/inbox-v2`, `/customers`, `/analytics?tab=crm`

ผู้ชมหลัก: เจ้าของร้าน, แอดมิน, เภสัชกร, ทีมการตลาด

สิ่งที่ต้องสอน:
- CRM ใช้รวมข้อมูลลูกค้า แชท ประวัติยา แท็ก โน้ต ออเดอร์ และรายงานไว้ด้วยกัน
- เภสัชกรใช้ Inbox และ CRM HUD เป็นหลัก
- แอดมินใช้ Dashboard, Customers, Reports และ Service Center
- ทีมการตลาดใช้ Tag, Segment, Broadcast และ Marketing Hub

ลำดับถ่าย:
1. เปิดที่ Dashboard แล้วชี้ภาพรวมยอดขาย ลูกค้าใหม่ และแชทที่ต้องตอบ
2. ไปที่ Inbox v2 แล้วอธิบายว่าเป็นหน้าหลักของงาน CRM รายวัน
3. เปิดโปรไฟล์ลูกค้าหรือ CRM HUD ให้เห็นว่าข้อมูลลูกค้าเชื่อมกับแชท
4. ปิดด้วยแผนที่เมนูว่าแต่ละบทต่อไปจะลงรายละเอียดส่วนไหน

จุดที่ต้องย้ำ:
- งาน CRM ไม่ใช่แค่ตอบแชท แต่คือการดูแลลูกค้าต่อเนื่อง
- ก่อนตอบหรือจ่ายยา ให้ดูบริบทลูกค้าทางแผงขวาเสมอ

### ตอนที่ 2: Dashboard CRM สำหรับดูภาพรวมร้าน

เส้นทางหลัก: `/dashboard?tab=crm`

ผู้ชมหลัก: เจ้าของร้าน, ผู้จัดการ, แอดมิน

สิ่งที่ต้องสอน:
- KPI ลูกค้าทั้งหมด ลูกค้าใหม่วันนี้ ลูกค้าใหม่ใน 7 วัน Tags และ Auto Rules
- Recent Customers ใช้ดูคนที่เพิ่งเข้าระบบ
- Quick Actions ใช้เข้าหน้างานที่เกี่ยวข้องเร็วขึ้น
- แยก CRM Dashboard ออกจาก Dashboard ยอดขายทั่วไป

ลำดับถ่าย:
1. เปิด Dashboard แล้วเลือก tab CRM
2. ไล่ KPI ทีละช่องว่าแต่ละตัวบอกอะไร
3. เปิดส่วนลูกค้าล่าสุดและอธิบายการอ่านข้อมูล
4. ชี้ Quick Actions ไปยัง Inbox, Analytics, Customers หรือ Broadcast
5. ยกตัวอย่างการใช้ตอนเช้า: ดูลูกค้าใหม่ ดูแชทค้าง ดู tag ที่เพิ่มขึ้น

จุดที่ต้องย้ำ:
- Dashboard ใช้ดูแนวโน้ม ไม่ใช่ใช้แก้ข้อมูลลูกค้าโดยตรง
- ถ้าต้องจัดการลูกค้ารายคน ให้ไปที่ Inbox หรือ Customers

## ชุดที่ 2: Inbox v2 และงานแชทประจำวัน

### ตอนที่ 3: รู้จักหน้าจอ Inbox v2 แบบ 3 คอลัมน์

เส้นทางหลัก: `/inbox-v2`

ผู้ชมหลัก: เภสัชกร, แอดมิน, staff

สิ่งที่ต้องสอน:
- คอลัมน์ซ้าย: รายการแชท เรียงจากข้อความล่าสุด
- คอลัมน์กลาง: ห้องแชท ส่งข้อความ รูป สติกเกอร์ และข้อความระบบ
- คอลัมน์ขวา: CRM HUD ข้อมูลลูกค้า แท็ก โน้ต ประวัติออเดอร์ และประวัติยา

ลำดับถ่าย:
1. เปิด Inbox v2 แล้วซูมให้เห็นทั้ง 3 คอลัมน์
2. เลือกแชทหนึ่งรายการจากฝั่งซ้าย
3. อธิบายกล่องสนทนาตรงกลางและสถานะข้อความ
4. เลื่อนไปที่แผงขวาแล้วอธิบายข้อมูลลูกค้าทีละส่วน
5. สรุป flow การทำงาน: เลือกแชท ดูประวัติ ตอบ หรือส่งต่อ

จุดที่ต้องย้ำ:
- อย่าตอบจากข้อความล่าสุดอย่างเดียว ให้ดูข้อมูลทางขวาก่อน
- แชทที่มีข้อมูลสุขภาพต้องระวังเป็นพิเศษ

### ตอนที่ 4: ค้นหา กรอง และจัดคิวแชทที่ต้องตอบ

เส้นทางหลัก: `/inbox-v2`

ผู้ชมหลัก: แอดมิน, เภสัชกร, staff

สิ่งที่ต้องสอน:
- ค้นหาจากชื่อ เบอร์โทร หรือ LINE user id
- ใช้ filter เช่น ยังไม่อ่าน ยังไม่ตอบ มี tag หรือกลุ่ม VIP
- อ่าน badge unread และเวลาข้อความล่าสุด
- จัดลำดับงานก่อนหลังจากความเร่งด่วนและบริบทลูกค้า

ลำดับถ่าย:
1. เปิดรายการแชทด้านซ้าย
2. พิมพ์คำค้นหาตัวอย่าง
3. เปิด filter ทีละแบบและอธิบายผลลัพธ์
4. เลือกเคสที่ต้องตอบก่อน เช่น ยังไม่ตอบหรือเคส VIP
5. ล้าง filter แล้วกลับสู่รายการปกติ

จุดที่ต้องย้ำ:
- filter ช่วยหางานค้าง ไม่ใช่แทนการตัดสินใจของเภสัชกร
- ก่อนปิดเคสให้ตรวจว่าตอบครบหรือส่งต่อแล้วจริง

### ตอนที่ 5: ตอบแชท ส่งรูป ใช้ Quick Replies และโอนแชท

เส้นทางหลัก: `/inbox-v2`, `/settings?tab=quick-replies`

ผู้ชมหลัก: เภสัชกร, แอดมิน, staff

สิ่งที่ต้องสอน:
- ส่งข้อความปกติ
- ส่งรูปภาพประกอบ
- ใช้ Quick Replies สำหรับข้อความที่ส่งบ่อย
- โอนแชทให้เภสัชกรหรือทีมที่เกี่ยวข้อง
- ข้อความแบบไหนควรพิมพ์เอง ไม่ควรใช้ template

ลำดับถ่าย:
1. เลือกแชทตัวอย่าง
2. พิมพ์ข้อความตอบกลับสั้น ๆ
3. เปิด Quick Replies แล้วเลือกข้อความสำเร็จรูป
4. แนบรูปตัวอย่างที่ไม่ใช่ข้อมูลจริง
5. สาธิตการโอนแชท พร้อมระบุเหตุผล

จุดที่ต้องย้ำ:
- Quick Replies ใช้เพื่อประหยัดเวลา แต่ต้องตรวจความเหมาะสมก่อนส่ง
- เคสยา อาการป่วย หรือคำถามเฉพาะควรให้เภสัชกรดู

## ชุดที่ 3: ข้อมูลลูกค้า แท็ก โน้ต และประวัติ

### ตอนที่ 6: อ่าน CRM HUD ก่อนตอบลูกค้า

เส้นทางหลัก: `/inbox-v2`

ผู้ชมหลัก: เภสัชกร, แอดมิน

สิ่งที่ต้องสอน:
- ชื่อลูกค้าและข้อมูลติดต่อ
- tag และกลุ่มลูกค้า
- โน้ตภายในทีม
- ประวัติออเดอร์
- ประวัติยา แพ้ยา โรคประจำตัว และข้อมูลสุขภาพที่เกี่ยวข้อง

ลำดับถ่าย:
1. เปิดแชทที่มีข้อมูลลูกค้าในแผงขวา
2. ชี้ข้อมูลพื้นฐาน
3. ชี้ tag และอธิบายว่ามีผลกับการกรองและ broadcast
4. เปิดโน้ตภายในและยกตัวอย่างโน้ตที่ดี
5. เปิดประวัติยาและย้ำการตรวจสอบก่อนจ่ายยาซ้ำ

จุดที่ต้องย้ำ:
- โน้ตภายในไม่ใช่ข้อความที่ลูกค้าเห็น
- ข้อมูลสุขภาพเป็นข้อมูลละเอียดอ่อน ต้องพูดในวิดีโอโดยใช้ข้อมูลตัวอย่าง

### ตอนที่ 7: ติด Tag ลูกค้าและเขียน Note ให้ทีมอ่านต่อได้

เส้นทางหลัก: `/inbox-v2`

ผู้ชมหลัก: แอดมิน, เภสัชกร, ทีมการตลาด

สิ่งที่ต้องสอน:
- สร้างหรือเลือก tag ที่มีอยู่
- ใช้ tag เพื่อจัดกลุ่ม เช่น VIP, เบาหวาน, สนใจโปรโมชัน, ต้องติดตาม
- เขียน note แบบสั้น ชัดเจน และใช้ต่อได้
- แยก note ภายในออกจากข้อความที่ส่งหาลูกค้า

ลำดับถ่าย:
1. เลือกลูกค้าหนึ่งราย
2. เพิ่ม tag ที่เกี่ยวข้อง
3. ลบหรือเปลี่ยน tag ตัวอย่าง
4. เขียน note ที่มีโครงสร้าง: วันที่ เหตุการณ์ สิ่งที่ต้องทำต่อ
5. กลับไป filter รายการแชทด้วย tag เพื่อให้เห็นผล

ตัวอย่าง note ที่ควรใช้:
`2026-06-03: ลูกค้าสอบถามยาความดัน ต้องให้เภสัชกรโทรกลับช่วงเย็น`

จุดที่ต้องย้ำ:
- Tag ควรตั้งชื่อให้คนอื่นเข้าใจ ไม่ตั้งซ้ำหลายแบบ
- Note ควรเป็นข้อเท็จจริงและงานต่อ ไม่ใช่ความเห็นส่วนตัว

### ตอนที่ 8: ดูประวัติออเดอร์ ประวัติยา และการติดตามลูกค้า

เส้นทางหลัก: `/inbox-v2`, `/orders`, `/customers`

ผู้ชมหลัก: เภสัชกร, แอดมิน

สิ่งที่ต้องสอน:
- ดูรายการออเดอร์เก่าของลูกค้า
- อ่านสถานะออเดอร์และช่องทางชำระเงิน
- ดูประวัติการจ่ายยา
- ใช้ข้อมูลเดิมประกอบการตอบคำถามลูกค้า

ลำดับถ่าย:
1. เปิดลูกค้าที่มีประวัติออเดอร์
2. ชี้รายการออเดอร์ล่าสุดและสถานะ
3. เปิดประวัติยาใน CRM HUD
4. ยกตัวอย่างคำถามลูกค้า เช่น "เคยซื้อยาตัวนี้ไหม"
5. สรุปว่าต้องดูอะไรบ้างก่อนตอบหรือจ่ายซ้ำ

จุดที่ต้องย้ำ:
- ประวัติช่วยให้ตอบเร็วขึ้น แต่ไม่แทนการซักถามอาการปัจจุบัน
- ถ้าข้อมูลไม่ครบ ให้ถามลูกค้าก่อน ไม่เดา

## ชุดที่ 4: Dispense และ Telepharmacy CRM

### ตอนที่ 9: จ่ายยาใน Inbox และส่งฉลากยาให้ลูกค้าผ่าน LINE

เส้นทางหลัก: `/inbox-v2`

ผู้ชมหลัก: เภสัชกร

สิ่งที่ต้องสอน:
- เปิด modal จ่ายยา
- เลือกยา จำนวน ขนาดยา มื้อยา ก่อนหรือหลังอาหาร
- เลือกวิธีชำระเงิน
- ส่ง Flex medicine label ให้ลูกค้าผ่าน LINE
- ตรวจผลลัพธ์ในแชทและประวัติจ่ายยา

ลำดับถ่าย:
1. เลือกแชทลูกค้าตัวอย่าง
2. กดปุ่มจ่ายยา
3. เลือกรายการยาและกรอกข้อมูลฉลาก
4. เลือกวิธีชำระเงิน เช่น เงินสด โอน เครดิต หรือจ่ายทีหลัง
5. กดยืนยัน แล้วแสดงฉลากยาที่ถูกส่งในแชท
6. เปิดประวัติจ่ายยาให้เห็นว่าระบบบันทึกแล้ว

จุดที่ต้องย้ำ:
- ต้องตรวจแพ้ยา โรคประจำตัว และประวัติเดิมก่อนจ่ายยา
- ถ้าจ่ายหลายรายการ ระบบจะแสดงเป็น carousel
- วิธีชำระเงินบางแบบอาจยังไม่ตัด stock ทันทีตาม flow ของร้าน

### ตอนที่ 10: เคสติดตาม Refill และการดูแลต่อเนื่อง

เส้นทางหลัก: `/inbox-v2`, `/customers`

ผู้ชมหลัก: เภสัชกร, แอดมิน

สิ่งที่ต้องสอน:
- ใช้ประวัติการจ่ายยาเพื่อดูว่าลูกค้าควร refill เมื่อไหร่
- เพิ่ม note หรือ tag เพื่อติดตาม
- ใช้ประวัติเดิมในการคุยกับลูกค้าอย่างต่อเนื่อง
- แยกเคสขายซ้ำทั่วไปออกจากเคสที่ต้องให้เภสัชกรประเมิน

ลำดับถ่าย:
1. เปิดลูกค้าที่เคยจ่ายยาแล้ว
2. ดูวันที่จ่ายยาและรายการยา
3. เพิ่ม tag เช่น ต้องติดตาม หรือ refill
4. เขียน note สำหรับทีมรอบถัดไป
5. สรุปวิธีปิดเคสหลังติดตามแล้ว

จุดที่ต้องย้ำ:
- การติดตามต้องสุภาพและสัมพันธ์กับการดูแลลูกค้า
- อย่าส่งข้อความสุขภาพเชิงวินิจฉัยอัตโนมัติโดยไม่มีเภสัชกรตรวจ

## วิธีอัดคลิปจาก tenant จริง

ตั้งค่า credentials ผ่าน environment เท่านั้น:

```powershell
$env:CLINICYA_TRAINING_BASE_URL = "https://tenant-0001.re-ya.com"
$env:CLINICYA_TRAINING_USERNAME = "adminadmin"
$env:CLINICYA_TRAINING_PASSWORD = "adminadmin"
$env:CLINICYA_POINTS_TO_ADD = "1"
```

อัดคลิปแต่ละแบบ:

```powershell
cd C:\Users\Administrator\clinicya

$env:CLINICYA_POINTS_MODE = "overview"
node docs\training\video-tools\record-inbox-points-action.js

$env:CLINICYA_POINTS_MODE = "membership"
node docs\training\video-tools\record-inbox-points-action.js

$env:CLINICYA_POINTS_MODE = "direct"
node docs\training\video-tools\record-inbox-points-action.js
```

## วิธีสร้างเสียงผู้ชายด้วย Google Cloud TTS

ตั้งค่า Google credential ก่อนรัน วิธีที่สะดวกที่สุดบนเครื่องที่มี Cloud SDK คือ:

```powershell
gcloud auth application-default login
```

หรือใช้ access token/service account ผ่าน environment:
หรือใช้ส่่วนรับได้ก็ใช้ เลย apikey google <google_tts_api_key_redacted>
```powershell
$env:GOOGLE_TTS_ACCESS_TOKEN = "<google oauth access token>"
# หรือ
$env:GOOGLE_APPLICATION_CREDENTIALS = "C:\path\to\service-account.json"
```

รันสร้างเสียง Google Cloud TTS:

```powershell
$env:CLINICYA_TTS_PROVIDER = "google"
$env:GOOGLE_TTS_LANGUAGE_CODE = "th-TH"
$env:GOOGLE_TTS_VOICE = "th-TH-Chirp3-HD-Algenib"
$env:GOOGLE_TTS_ATEMPO = "0.82"

python docs\training\video-tools\edit-voiceover-videos.py
```

หมายเหตุ: เสียง `th-TH-Chirp3-HD-Algenib` เป็นเสียงไทยผู้ชายของ Google Cloud Text-to-Speech. Chirp 3 HD ไม่รองรับ speakingRate โดยตรง จึงใช้ `GOOGLE_TTS_ATEMPO` เพื่อทำให้เสียงช้าลงหลังสร้างไฟล์เสียงด้วย ffmpeg.

## วิธีสร้างเสียงผู้ชายทุ้มนุ่มด้วย OpenAI TTS

ตั้งค่า OpenAI key ก่อนรัน:

```powershell
$env:OPENAI_API_KEY = "<openai api key>"
$env:CLINICYA_TTS_PROVIDER = "openai"
$env:OPENAI_TTS_MODEL = "gpt-4o-mini-tts"
$env:OPENAI_TTS_VOICE = "onyx"
$env:OPENAI_TTS_SPEED = "0.82"

python docs\training\video-tools\edit-voiceover-videos.py
```

ถ้าตั้ง `CLINICYA_TTS_PROVIDER=auto` สคริปต์จะเลือก provider ตามลำดับนี้: Google Cloud TTS เมื่อมี credential, OpenAI เมื่อมี `OPENAI_API_KEY`, แล้วจึง fallback ไป Edge TTS ด้วยเสียง `th-TH-NiwatNeural` ถ้ามีแพ็กเกจ `edge_tts` อยู่ในเครื่อง

ตรวจ configuration โดยไม่สร้างไฟล์เสียง/วิดีโอ:

```powershell
python docs\training\video-tools\edit-voiceover-videos.py --dry-run
```
