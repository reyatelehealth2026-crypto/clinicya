# คู่มือใช้งาน reya ฉบับละเอียดมาก (ใช้งานจริงทั้งระบบ)

อัปเดตล่าสุด: 17 พฤษภาคม 2569  
เวอร์ชัน: 3.0 (ฉบับละเอียดมาก)  
รูปแบบเอกสาร: คู่มือใช้งานสำหรับทีมงานและลูกค้า  
เหมาะสำหรับ: Owner, Admin, Pharmacist, Marketing, Staff, Tech และลูกค้า LINE OA / Mini App

เอกสารฉบับนี้ทำขึ้นเพื่อให้คนที่ไม่เคยใช้ระบบมาก่อนก็สามารถอ่านแล้วเข้าใจ flow การทำงานของระบบ reya ได้ครบที่สุด โดยอธิบายทั้ง
- เมนูแต่ละส่วนใช้ทำอะไร
- งานไหนควรเริ่มจากตรงไหน
- กรอกข้อมูลอะไรแล้วมีผลกับอะไรต่อ
- งานแต่ละบทบาทควรดูหน้าจอไหนบ่อย
- ถ้าเกิดปัญหา ควรไล่เช็กอะไรเป็นลำดับแรก

> ถ้าต้องการอ่านแบบเร็ว ให้ดูหัวข้อ “สรุป workflow ตามบทบาท” ก่อน  
> ถ้าต้องการอ่านแบบครบ ให้ไล่จากต้นเอกสารลงไปตามลำดับ

## จุดประสงค์ของระบบ reya

reya เป็นระบบสำหรับร้านยา/คลินิกที่รวมงานหน้าร้านและงานดิจิทัลไว้ด้วยกันในระบบเดียว โดยมีแกนหลัก 4 เรื่อง

1. **สื่อสารกับลูกค้า** ผ่าน LINE OA และ Inbox หลังบ้าน  
2. **ทำงานเภสัช** เช่น จ่ายยา ติดตามการใช้ยา และแจ้ง Refill  
3. **ทำธุรกรรมการขาย** เช่น ออเดอร์ การชำระเงิน การจัดส่ง และสต๊อก  
4. **ดูแลความสัมพันธ์ลูกค้า** เช่น สมาชิก แต้ม รางวัล Broadcast และแคมเปญอัตโนมัติ

พูดง่าย ๆ คือ หากร้านใช้งานครบ flow ระบบนี้จะเชื่อมกันแบบนี้:

ลูกค้าทัก LINE → ทีมตอบใน Inbox → เภสัชกรจ่ายยา/แนะนำสินค้า → ระบบสร้างออเดอร์ → ลูกค้าชำระเงิน → ทีมจัดส่ง/ปิดงาน → ระบบติดตามยาใกล้หมด → ลูกค้ากลับมาซื้อซ้ำ → ทีมทำ Broadcast / Membership เพื่อรักษาฐานลูกค้า

## สรุป workflow ตามบทบาท

### 1) Owner / Super Admin
เหมาะสำหรับผู้ดูภาพรวมทั้งธุรกิจและควบคุมการตั้งค่าระดับสูง

สิ่งที่มักทำบ่อย:
- ดู Dashboard ภาพรวม
- ตรวจยอดขายและสถานะงานค้าง
- จัดการบัญชี LINE OA และ API key
- เพิ่ม/ลบผู้ใช้งาน และกำหนดสิทธิ์
- ดูการตั้งค่า Mini App, LIFF และ integration สำคัญ

### 2) Admin
เหมาะสำหรับคนที่คุมงานประจำวันของระบบ

สิ่งที่มักทำบ่อย:
- ดู Dashboard
- เช็ก Inbox และกระจายงาน
- ตรวจออเดอร์ค้างชำระ / ค้างจัดส่ง
- ดูรายชื่อลูกค้าและแท็ก
- ประสานงานกับเภสัชกร การตลาด และทีม Tech

### 3) Pharmacist
เหมาะสำหรับทีมเภสัชกรที่ให้คำปรึกษาและจ่ายยา

สิ่งที่มักทำบ่อย:
- เปิด Inbox เพื่อตอบลูกค้า
- จ่ายยา
- ตรวจความถูกต้องของ dosage / timeOfDay / before-after meal
- ดูประวัติยาเดิม
- ติดตามยาใกล้หมดและส่ง Refill
- ตรวจว่าลูกค้าได้รับฉลากยาเรียบร้อยหรือไม่

### 4) Marketing
เหมาะสำหรับทีมดูแลยอดขายและการกลับมาซื้อซ้ำ

สิ่งที่มักทำบ่อย:
- จัดการ Broadcast
- ทำ Drip Campaign
- ใช้แท็กหรือ segment ในการเลือกกลุ่มลูกค้า
- จัดการ Membership, แต้ม และรางวัล
- ปรับ Rich Menu ให้ตรงกับแคมเปญ

### 5) Staff
เหมาะสำหรับพนักงานที่ช่วยงานหน้าบ้านและหลังบ้าน

สิ่งที่มักทำบ่อย:
- ช่วยตอบแชททั่วไป
- ดูออเดอร์และสถานะการชำระ
- ช่วยตรวจสลิป
- ช่วยเช็กสต๊อกและงานคลังพื้นฐาน

### 6) Tech
เหมาะสำหรับผู้ดูแลการเชื่อมระบบ

สิ่งที่มักทำบ่อย:
- ตรวจ webhook และการเชื่อม LINE OA
- ดูการตั้งค่า Telegram
- ตรวจ LIFF / Mini App / integration ต่าง ๆ
- ช่วยแก้ปัญหาข้อความไม่เข้า ระบบไม่ยิง หรือ token ผิด

# ส่วนที่ 1: สำหรับผู้ใช้งานระบบ

## 0) Setup ครั้งแรกผ่าน Onboarding Wizard

ระบบ reya มี **Setup Wizard** สำหรับร้านที่เปิดใช้งานครั้งแรก ไม่ต้องตั้งค่าทีละหน้าให้ปวดหัว — wizard จะพาเดิน 7 ขั้นรวบทุกอย่างไว้ในจุดเดียว

### เส้นทาง
- เปิดอัตโนมัติหลัง login ครั้งแรก (ถ้า `admin_users.onboarding_completed = 0`)
- หรือเข้าเองที่ `/onboarding/wizard.php?step=1`

### 7 ขั้นของ Wizard
1. **ข้อมูลร้าน** — ชื่อ, ที่อยู่, เบอร์, เวลาเปิด, โลโก้ → บันทึกใน `shop_settings`
2. **เชื่อม LINE OA** — Channel ID + Access Token + Secret + Webhook URL ที่ต้อง paste ไป LINE Developers → `line_accounts`
3. **LIFF** — LIFF ID + endpoint URL → `liff_apps` (ใช้สำหรับ Mini App / Shop / Order page)
4. **ระบบชำระเงิน** — เลข PromptPay / เลขบัญชี + ชื่อธนาคาร → `shop_settings`
5. **เภสัชกรคนแรก** — ชื่อ + license + รูป → `pharmacists` (active + available)
6. **ตั้งค่า AI (optional)** — เลือก Gemini/OpenAI + API key → `ai_settings` (ข้ามได้ มาตั้งทีหลังได้)
7. **เสร็จสมบูรณ์** — สรุปสิ่งที่ตั้งค่าไป + ปุ่มเข้า dashboard

### ปุ่มในแต่ละขั้น
- **← ย้อน** — กลับขั้นก่อนหน้า
- **บันทึก & ถัดไป** — บันทึกข้อมูลขั้นปัจจุบัน + ไปต่อ
- **ข้ามทั้งหมด** (มุมขวาบน) — set `onboarding_skipped=1` แล้วเข้า dashboard เลย

### หลังจบ wizard
- ระบบ set `onboarding_completed=1` + `onboarding_completed_at=NOW()`
- จะถูกชวนเปิด **Admin Tour** (ดูข้อ 18.x) เพื่อแนะนำเมนูหลัก 8 จุด

### ถ้าอยากทำ wizard ใหม่
- Owner เข้า DB → `UPDATE admin_users SET onboarding_completed=0 WHERE id=<id>` แล้ว login ใหม่
- หรือเข้า URL `/onboarding/wizard.php?step=1` ตรงๆ ก็ได้

## 1) เริ่มต้นใช้งานและบทบาท

### วิธีเข้าใช้งาน
1. เข้า `https://re-ya.com/auth/login`
2. ใส่ username และ password ที่แอดมินให้
3. เข้าสู่ระบบ
4. ระบบจะพาไปยังหน้าที่ตรงกับสิทธิ์ของแต่ละคน

### บทบาทของผู้ใช้งาน

**Owner / Super Admin**
- ใช้งานได้ทุกส่วน
- จัดการ API key ได้
- จัดการบัญชี LINE ได้
- จัดการบุคลากรและสิทธิ์ได้

**Admin**
- ใช้งานได้เกือบทุกอย่าง
- มักไม่มีสิทธิ์จัดการ API key และ role management

**Pharmacist (เภสัชกร)**
- ใช้ Inbox
- จ่ายยา
- ติดตาม Refill
- ดูข้อมูลลูกค้า
- ดูและจัดการสต๊อกบางส่วน

**Marketing**
- ใช้ Broadcast
- ใช้ Drip Campaign
- จัดการ Rich Menu
- ดูแล Membership

**Staff**
- ใช้ Inbox
- ดูออเดอร์
- ทำงานสต๊อกพื้นฐาน

**Tech**
- ตั้งค่าระบบ
- ดูการเชื่อม LINE
- ดู Telegram และ integration ต่าง ๆ

### ถ้ายังไม่เห็นเมนูที่ควรมี
ให้ตรวจ 2 เรื่องก่อน
- ล็อกอินด้วยบัญชีถูกต้องหรือไม่
- บทบาทที่ได้รับตรงกับงานหรือไม่

## 3) Dashboard ภาพรวม

เส้นทาง: `/dashboard`  
สิทธิ์ที่มักเข้าได้: Admin / Owner

### หน้านี้ใช้ดูอะไร
- ยอดขายวันนี้
- ยอดขายรายสัปดาห์
- ยอดขายรายเดือน
- จำนวนออเดอร์ที่รอดำเนินการ
- จำนวนออเดอร์ที่เสร็จแล้ว
- ลูกค้าใหม่
- แชทที่ยังไม่ได้ตอบ
- กราฟยอดขายย้อนหลัง 30 วัน
- สินค้าขายดี 10 อันดับแรก

### Tabs ที่อาจพบ
- Executive
- CRM
- Odoo (ถ้าเปิดใช้งาน)

### ใช้เมื่อไร
- เช็กภาพรวมตอนเริ่มงาน
- เช็กว่าวันนี้มีออเดอร์ค้างไหม
- เช็กว่ามีแชทที่ยังไม่ตอบหรือไม่
- ดูยอดขายและสินค้าขายดี

## 4) Inbox และการคุยกับลูกค้า

เส้นทาง: `/inbox-v2` หรือ `/messages`

### หน้าจอแบ่งเป็น 3 ส่วน

**ซ้าย: รายการแชท**
- เรียงจากแชทล่าสุด
- มี badge บอก unread

**กลาง: หน้าต่างแชท**
- คุยข้อความได้
- ส่งรูปได้
- ส่ง sticker ได้
- เห็นฉลากยาและข้อความระบบในแชท

**ขวา: ข้อมูลลูกค้า**
- ชื่อลูกค้า
- แท็ก
- โน้ตภายใน
- ประวัติออเดอร์
- ประวัติยา

## 5) การจ่ายยา

เส้นทาง: Inbox > เลือกลูกค้า > ปุ่ม `จ่ายยา`

การจ่ายยาเป็นจุดสำคัญของระบบ เพราะเมื่อกดยืนยันแล้ว ระบบจะสร้างข้อมูลหลายอย่างต่อเนื่อง

### ขั้นตอนการจ่ายยา
1. เลือกลูกค้าใน Inbox
2. กดปุ่ม `จ่ายยา`
3. ตรวจหรือกรอกชื่อร้านและชื่อเภสัชกร
4. กด `เพิ่มสินค้า`
5. เลือกยาจากรายการ
6. กรอกรายละเอียดยาแต่ละตัว
7. เลือกวิธีชำระเงิน
8. กดยืนยัน

### ความหมายของแต่ละช่องที่ต้องกรอก

**จำนวน (qty)**
- คือจำนวนแพ็กที่จ่ายจริง
- เช่น 1 กล่อง, 1 แผง, 1 หลอด

**ขนาดยา (dosage)**
- คือจำนวนที่กินต่อ 1 มื้อ
- เช่น 1 เม็ดต่อมื้อ
- ไม่ใช่จำนวนรวมทั้งหมดที่จ่าย

**มื้อ (timeOfDay)**
- เลือกว่ากินช่วงไหน

- เช่น เช้า, กลางวัน, เย็น, ก่อนนอน

**ก่อน/หลังอาหาร**
- เลือกอย่างใดอย่างหนึ่งตามวิธีใช้ยา

**คำแนะนำพิเศษ**
- เช่น ดื่มน้ำมาก
- ห้ามดื่มแอลกอฮอล์
- ง่วงซึม ไม่ควรขับรถ

**ข้อบ่งใช้ (indication)**
- ระบุว่ายานี้ใช้เพื่ออะไร
- เช่น แก้แพ้, ลดไข้, บรรเทาอาการไอ

### ข้อควรระวังที่สำคัญมาก

ห้ามกรอก `dosage` เป็นจำนวนรวมทั้งหมดที่จ่าย

ตัวอย่างที่ถูก
- จ่ายยา 10 เม็ด
- ให้กินครั้งละ 1 เม็ด วันละ 3 มื้อ
- ต้องกรอก dosage = 1

ตัวอย่างที่ผิด
- ถ้ากรอก dosage = 10
- ระบบจะเข้าใจว่ากินครั้งละ 10 เม็ด
- ถ้าวันละ 3 มื้อ จะกลายเป็น 30 เม็ดต่อวันทันที

### สูตรที่ระบบใช้คำนวณ
- วันละ = ขนาดยาต่อมื้อ x จำนวนมื้อ
- จำนวนวัน = จำนวนยาทั้งหมด / ปริมาณที่กินต่อวัน

### วิธีชำระเงินที่เลือกได้

**เงินสด**
- ออเดอร์จะเป็นสถานะชำระแล้ว
- ระบบตัดสต๊อกทันที

**โอน**
- ออเดอร์จะเป็นรอจ่ายเงิน
- ลูกค้าจะเห็นปุ่มชำระเงินใน Flex Message

**ภายหลัง**
- ออเดอร์จะเป็นรอจ่ายเงิน
- ลูกค้าค่อยมาชำระทีหลัง

### หลังกดยืนยันแล้ว ระบบทำอะไรให้ทันที
- บันทึกประวัติการจ่ายยา
- สร้างออเดอร์ในระบบออเดอร์
- ส่งฉลากยาเข้า LINE ลูกค้า
- เริ่มการติดตามยาเพื่อเตือน Refill

### ถ้าจ่ายยาแล้วควรเช็กอะไรต่อ
- ลูกค้าได้รับฉลากยาหรือไม่
- ออเดอร์ถูกสร้างหรือไม่
- สถานะการชำระตรงกับที่เลือกหรือไม่
- สต๊อกถูกตัดถูกต้องหรือไม่

## 6) การติดตามยาใกล้หมดและ Refill

เส้นทางเข้าได้ 3 แบบ
- Sidebar > งานบริการคลินิก > ติดตามการจ่ายยา
- Pharmacy > tab จ่ายยา > banner ด้านบน
- URL `/dispense-tracking`

### หน้านี้ใช้ทำอะไร
ใช้ติดตามว่าลูกค้าคนไหนกำลังใช้ยาอยู่ ยาตัวไหนใกล้หมด และควรเตือนใครบ้าง

### สถานะหลักด้านบน

**กำลังใช้ยาอยู่**
- รายการที่ยังอยู่ในช่วงใช้ยา

**ใกล้หมดใน 3 วัน**
- รายการที่ควรเตือนลูกค้าแล้ว

**ครบกำหนดแล้ว**
- ยาน่าจะหมดแล้ว แต่ลูกค้ายังไม่ได้ Refill

### ค้นหาและกรอง
กรองได้เช่น
- กำลังใช้ยา
- ครบกำหนด
- ทั้งหมด

ค้นหาได้จาก
- ชื่อลูกค้า
- ชื่อยา

### สิ่งที่เห็นในการ์ดแต่ละรายการ
- ชื่อลูกค้า
- สถานะ LINE
- ชื่อยา
- รหัสยา
- วันที่จ่าย
- ผ่านมาแล้วกี่วัน
- ปริมาณยาที่เหลือโดยประมาณ
- ใช้วันละกี่หน่วย
- แถบ progress
- วันคาดว่ายาจะหมด
- สีสถานะ เขียว / เหลือง / แดง
- ปุ่มส่งแจ้งเตือน
- ลิงก์เปิดแชท

### วิธีส่งแจ้งเตือนแบบแมนนวล
1. กด `ส่งแจ้งเตือน`
2. ยืนยันใน popup
3. ระบบส่ง Flex Refill ให้ลูกค้าทันที
4. ระบบบันทึก log ลงในแชท
5. ปุ่มจะเปลี่ยนเป็น `ส่งแล้ว`

### การแจ้งเตือนอัตโนมัติ
ระบบมีการเตือนให้อัตโนมัติ โดยหลักคือ
- ทำงานทุกวันเวลา 9:00
- ส่งเฉพาะรายการที่เหลือไม่เกิน 3 วัน
- ไม่ส่งซ้ำใน 7 วัน

- เคารพการตั้งค่าของลูกค้าที่ปิดการเตือนยา

### ถ้าส่งเตือนไม่ได้ ให้เช็กก่อน
- ลูกค้ายังเป็นเพื่อนกับ OA หรือไม่
- โควต้า push message เต็มหรือไม่
- token หรือการเชื่อม LINE มีปัญหาหรือไม่

## 18.5) ศูนย์ช่วยเหลือ (Help Hub) + Admin Tour

ระบบ reya มีจุดช่วยเหลือในตัวสำหรับทีมงาน ไม่ต้องเปิดคู่มือนี้ทีละครั้ง

### Help Hub
เส้นทาง: `/help` หรือคลิก **📚 ศูนย์ช่วยเหลือ** ใน sidebar กลุ่ม "ตั้งค่าร้านค้า"  
หรือกด **floating help button** (ไอคอน `?` มุมขวาล่างทุกหน้า admin)

#### Help Hub มีอะไร
- Card grid 7 tutorials หลัก ครอบคลุมงานยอดนิยม
- Filter ตามหมวด: เริ่มต้น / งานประจำวัน / การตลาด / ขั้นสูง
- ช่องค้นหา (filter card เมื่อพิมพ์)
- คลิก card → modal step-by-step (5 ขั้น/tutorial) พร้อมรูปประกอบจาก production

#### 7 Tutorials ที่มี
1. **วิธีจ่ายยาให้ลูกค้า** — pack size + dosage + meals + วิธีชำระ + auto-track refill
2. **วิธีรับสาย Video Call** — ringtone + accept + chat overlay + ดูประวัติ
3. **วิธีเพิ่มสินค้าใหม่** — รูป + ราคา + stock + pack size + Mini App toggle
4. **วิธีตอบแชท + ติดแท็กลูกค้า** — quick reply + tag + ดูประวัติ + โอนแชท
5. **วิธีสร้าง Broadcast** — เลือก audience by tag + Flex + schedule + สถิติ
6. **วิธีจัดการสมาชิก + แต้มสะสม** — tier + rules + reward + manual adjust
7. **วิธีใช้ระบบติดตาม Refill** — progress + manual notify + cron 09:00

### Admin Tour
ใช้ครั้งแรกหลังจาก wizard เสร็จ ระบบเปิดให้อัตโนมัติ (ถ้าตั้ง URL `?after=wizard`)  
หรือเปิดเองได้จาก **user menu dropdown** มุมขวาบน → "🎓 ทัวร์ระบบ"

#### Tour พา walk 8 จุด
1. Sidebar — เมนูจัดกลุ่มตาม workflow
2. Inbox — แชท + จ่ายยา + แท็ก รวมที่เดียว
3. Pharmacy/Dispense — ระบบจ่ายยา + ฉลากยา LINE
4. Dispense Tracking — ติดตามยาคงเหลือ + เตือน 3 วัน
5. Orders — จัดการออเดอร์ + ยืนยันสลิป + WMS
6. Inventory — คลังสินค้า + ปรับสต๊อก
7. Broadcast — โปรโมชั่นผ่าน LINE + กรองตามแท็ก
8. Settings + Help — ตั้งค่าระบบ + ดู tutorial ใหม่ได้ตลอด

#### ปุ่มในแต่ละ stop
- **ข้าม** — ปิด tour (set `localStorage.admin_tour_v1_done=1`)
- **← ย้อน** / **ถัดไป →** — เดินไปมาระหว่าง stops
- **เสร็จ** — ปิด tour + บันทึกว่าจบแล้ว

#### ถ้าอยากดู tour อีกครั้ง
- ลบ `localStorage.admin_tour_v1_done` แล้ว reload หน้า
- หรือคลิก "🎓 ทัวร์ระบบ" ใน user menu

### เมื่อไรควรใช้
- **พนักงานใหม่:** เปิด tour ทันทีหลัง login ครั้งแรก แล้วเข้า help hub ดู tutorial ตามงานที่จะทำ
- **เภสัชกรไม่เคยใช้ระบบจ่ายยา:** เปิด tutorial "วิธีจ่ายยา" ก่อน
- **มาร์เก็ตติ้งจะส่ง broadcast แรก:** เปิด tutorial "วิธีสร้าง Broadcast"

# ภาคผนวก: จุดที่ควรเทรนพนักงานใหม่เป็นพิเศษ

## A. 10 เรื่องที่พนักงานใหม่ควรรู้ตั้งแต่วันแรก
1. ระบบนี้ไม่ได้มีแค่แชท แต่ทุกอย่างเชื่อมถึงกัน
2. การจ่ายยา 1 ครั้ง อาจสร้างทั้งประวัติยา ออเดอร์ ฉลากยา และ Refill tracking
3. ถ้ากรอก dosage ผิด จะกระทบการคำนวณทั้งระบบ
4. ลูกค้าไม่ได้รับข้อความจากระบบ มักเกี่ยวกับ LINE OA, การเป็นเพื่อน หรือ quota
5. ออเดอร์จากการจ่ายยาต้องตามผ่าน note หรือ dispense_id ได้
6. แท็กช่วยงานการตลาดและการดูแลลูกค้าระยะยาว
7. สต๊อกไม่ตรง ให้ดู movement log ก่อนเสมอ
8. Broadcast ส่งไม่ถึงทุกคนไม่จำเป็นว่าเป็น bug อาจเป็นเพราะลูกค้าบล็อก OA
9. ข้อมูล PDPA และ consent เป็นเรื่องสำคัญ ห้ามส่งต่อข้อมูลลูกค้าโดยไม่จำเป็น
10. ถ้าไม่แน่ใจว่าหน้าไหนต้องใช้ ให้เริ่มจาก Inbox หรือ Orders ก่อนเสมอ

## B. Checklist ก่อนจบงานในแต่ละวัน

### สำหรับเภสัชกร
- ตอบแชทสำคัญครบหรือยัง
- ลูกค้าที่จ่ายยาแล้วได้รับฉลากยาครบหรือไม่
- มีรายการใกล้หมดที่ควรเตือนหรือยัง
- มีเคสไหนต้องส่งต่อหรือใส่โน้ตภายในไหม

### สำหรับแอดมิน
- มีออเดอร์รอชำระค้างหรือไม่
- มีออเดอร์ที่ควรอัปเดตเป็น shipped/completed หรือไม่
- มีแชท unread สะสมหรือไม่
- มีสินค้าตัวไหนใกล้หมดและต้องแจ้งจัดซื้อไหม

### สำหรับมาร์เก็ตติ้ง
- Campaign ที่ยิงไปมี failed ผิดปกติหรือไม่
- Segment/Tag ถูกต้องก่อนยิงรอบถัดไปหรือไม่
- Rich Menu ยังตรงกับโปรโมชั่นปัจจุบันหรือไม่
- รางวัล/แต้ม/ข้อเสนอใน Mini App ยังอัปเดตอยู่หรือไม่

## C. ลำดับการไล่เช็กเมื่อระบบดูผิดปกติ
1. ปัญหาเกิดที่หน้าไหน
2. ปัญหาเกิดกับผู้ใช้คนเดียวหรือทุกคน
3. เกี่ยวข้องกับ LINE OA หรือไม่
4. เกี่ยวข้องกับการจ่ายยา ออเดอร์ หรือสต๊อกหรือไม่
5. มี error message ระบุชัดเจนไหม
6. ถ้าเกี่ยวกับข้อความไม่เข้า ให้เช็ก token / quota / friend status
7. ถ้าเกี่ยวกับออเดอร์ ให้ดู note, payment status, tracking status
8. ถ้าเกี่ยวกับสต๊อก ให้ดู movement log และการตัดสต๊อกจาก dispense/order

## D. สรุป flow ที่สำคัญที่สุดของระบบ
- จุดเริ่มงานบริการ: Inbox
- จุดเริ่มงานยา: Dispense
- จุดเริ่มงานขาย: Orders
- จุดเริ่มงานสต๊อก: Inventory
- จุดเริ่มงานการตลาด: Broadcast / Membership
- จุดเริ่มงานเชื่อมระบบ: Settings
